# Cyrush 
2D 오토 횡스크롤 슈팅게임

##  프로젝트 소개
'Cyrush'는 기획부터 최종 빌드까지 게임 개발의 전체 사이클을 경험하기 위해 제작한 대학교 졸업작품입니다. 
전방에서 몰려오는 적들을 처치하고 무기를 업그레이드하는 '뱀파이어 서바이버' 장르의 핵심 로직을 유니티로 직접 구현했습니다.

##  핵심 구현 내용
* **1인 풀사이클 개발:** 단순한 프로토타입을 넘어, 기획 - 리소스 적용 - 코어 로직 - 빌드까지 하나의 게임을 끝까지 완성해 내는 근성을 배웠습니다.
* **몬스터 웨이브 및 성장 시스템:** 시간이 지날수록 난이도가 올라가는 스폰 로직과 플레이어의 경험치/스킬 성장 시스템을 구현했습니다.
* **메모리 및 프레임 최적화 경험:** 수많은 몬스터와 투사체가 생성/파괴될 때 발생하는 부하를 막기 위해 '오브젝트 풀링(Object Pooling)'을 적용했으며, 특히 엄청난 수의 총알이 생성되는 보스의 탄막 패턴에는 '파티클 시스템(Particle System)'의 충돌 판정을 활용해 프레임 드랍(렉)을 방지하는 최적화를 시도했습니다

##  Developer's Note (개발자 코멘트)
이 프로젝트는 저에게 '개발자로서의 뼈저린 오답 노트'이자 성장의 밑거름입니다. 당시에 기능 구현에만 급급하여 남겼던 아쉬운 코드들을 덮어두지 않고, 현재는 이를 분석하며 더 나은 구조를 고민하는 레퍼런스로 활용하고 있습니다.

* **탄막 최적화의 시행착오와 리팩토링 계획**
적의 탄막을 오브젝트 풀링으로 처리함에도 발생하는 렉을 우회하기 위해, 보스 패턴에는 파티클 시스템(Particle System)의 충돌 판정을 활용하여 탄막을 흩뿌리는 최적화를 시도했습니다. 
하지만 당시 구조적 지식의 한계로 인해, 파티클을 제어할 때마다 `BulletParticle AutoF1 = GameObject.Find("FTri1")...` 와 같이 무거운 `Find()` 함수를 남발하는 하드코딩을 작성했습니다. 
**지금 동일한 로직을 리팩토링한다면**, `Start()`에서 한 번만 찾아 캐싱(Caching)해두거나, Inspector 창에서 총구들을 배열(Array)이나 리스트(List)로 한꺼번에 할당받아 `for`문으로 순회하며 발사하는 구조로 개선할 것입니다.

* **객체지향과 FSM에 대한 고민**
잦은 물리 버그와 엉킨 로직을 마주하며, "어떻게 하면 입력과 물리 연산을 분리하고 객체지향적으로 짤 수 있을까?"를 치열하게 고민하게 되었습니다. 현재는 과거의 코드를 교보재 삼아, FSM(상태 머신) 도입과 로직 분리를 집중적으로 공부하며 기본기를 다지고 있습니다.
